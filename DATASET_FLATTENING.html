Caleyez Project · Technical Methodology Report

Dataset Preparation and Label-Space Consolidation
for the Global Food-Classification Model

YOLOv11 baseline · May 2026

Abstract. This report documents the data preparation pipeline applied to the global food-image dataset prior to retraining the baseline convolutional classifier (YOLOv11). The procedure consolidates an inconsistent 142-class label space into 133 well-defined classes through three operations — semantic merging, label normalization, and removal of out-of-scope or noisy classes — and then re-partitions the data into reproducible 70/20/10 train/validation/test splits. A two-stage de-duplication step (exact and perceptual) is introduced to eliminate cross-split data leakage, a known source of optimistic bias in reported accuracy. The original dataset is preserved unaltered; all transformations are deterministic and fully auditable.

1. Motivation

Prior evaluation of the classification system indicated that overall accuracy was constrained by the quality of the underlying classifier rather than by downstream re-ranking logic. In addition, an inconsistency audit of the dataset revealed three categories of defect: (i) redundant fine-grained classes that fragment visually similar samples, (ii) non-standardized folder labels (inconsistent casing, whitespace, and spelling), and (iii) duplicated images shared between the training and test partitions. The last of these is particularly significant, as train/test leakage inflates measured test accuracy and undermines the validity of any subsequent comparison. The pipeline described here addresses all three defects to establish a clean and defensible baseline.

2.4 Classes retained without modification

Several groups of visually overlapping classes (e.g. raw-beef preparations, raw-fish preparations, pepper varieties, and rice dishes) were deliberately retained as distinct labels. Merging them would discard semantically meaningful granularity; the limited separability of such groups is attributable to model capacity rather than to label definition, and is therefore better addressed through model improvement than through label coarsening.

3. De-duplication and Leakage Prevention

To guarantee that no image — nor a near-identical variant of it — appears in more than one partition, a two-stage de-duplication procedure is applied prior to splitting. The fundamental unit of partitioning is therefore a content cluster, never an individual file.

  1. Exact duplicates. A SHA-1 digest is computed over the raw bytes of each image. Byte-identical copies are collapsed to a single representative and the redundant copies are discarded. This step removes genuine train/test leakage.
  2. Near-duplicates. A 64-bit perceptual difference hash (dHash) is computed for each representative; images whose hashes differ by a Hamming distance of at most five are grouped into a single cluster. Near-duplicates are not discarded — they contribute legitimate visual variance — but the entire cluster is assigned to one partition.

Correctness was confirmed by a per-class verification pass asserting that no source file path is assigned to more than one partition.

4. Re-partitioning

All surviving images were pooled by final label and partitioned by whole clusters to approximate a 70% training / 20% validation / 10% test ratio. Partitioning uses a fixed random seed (42), making the split fully reproducible. A manifest file (split_manifest.csv) records the provenance of every output image — its source partition, source class, and original filename.

5. Results

The consolidation reduced the label space from 142 to 133 classes. Of the pooled images, exact de-duplication removed 1,003 byte-identical copies, and 522 near-duplicate pairs were co-located within a single partition. The resulting dataset contains 99,307 images distributed as shown in Table 4.

6. Reproducibility and Data Integrity

  • Non-destructive. The procedure operates in copy mode; the original dataset is retained unmodified as an archival reference.
  • Deterministic. A fixed random seed yields an identical partition on every execution.
  • Auditable. A per-image provenance manifest accompanies the dataset.
  • Self-contained. The full pipeline is implemented in a single parameterized script, enabling exact replication.

7. Threats to Validity

Two limitations are noted for transparency. First, the dataset exhibits substantial class imbalance: ingredient-level classes contain on the order of 70–200 images, whereas prepared-dish classes contain approximately 1,000 (and merged classes up to 3,000). This imbalance should be mitigated during training (e.g. via class-balanced sampling or loss weighting). Second, the label taxonomy mixes two granularities — single raw ingredients and composed dishes — which increases intra-task difficulty. Both factors are properties of the source data rather than of the preparation procedure, and are documented here to inform interpretation of subsequent results.
