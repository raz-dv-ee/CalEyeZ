## Arbiter Pipeline — Run Order
```powershell
python arbiter\data\generate_reranker_dataset.py       # → arbiter/data/reranker_dataset.csv
python arbiter\train\train_reranker_xgb.py             # → arbiter/train/reranker_xgb.ubj
python arbiter\train\evaluate_system.py                # → arbiter/train/system_evaluation_results.csv
```

## What's NOT in the repo (gitignored — too large / regenerable)
- `datasets/` — image datasets
- `*.pt` epoch checkpoints — only `best.pt` of each final run is kept
- `*_dataset.csv` — re-generated by the data-gen script (e.g. `reranker_dataset.csv`)
- `*_results.csv` — re-generated by the evaluation script (e.g. `system_evaluation_results.csv`)

> Detailed architecture, the v1→v5 Arbiter version history, evaluation metrics,
> and the optimisation TODO list live in **`SYSTEM_STATE.md`** (project root).

## Changelog

### 2026-05-31 — Initial push
- Added training scripts, data.yaml, HTML docs
- Added runs for Global and Israeli models (metrics + best.pt weights)

### 2026-05-31 — Arbiter Re-Ranker pipeline
- Added `arbiter/` folder: Pointwise XGBoost Re-Ranker (data_gen → train → evaluate)
- Arbiter evolved v1 → v5:
  - v1: baseline `scale_pos_weight` — Israeli accuracy collapsed (28.2%)
  - v2: instance weighting — over-corrected (Global 68.7%)
  - v3: normalize-last 1:1 parity — Israeli 84.1% but Global still 74.9%
  - v4: evidence-based routing — 9 features; balanced but hurt Global (80.3% overall)
  - v5: **tunable domain dial (α=0.3) + 6 interaction features** — overall **84.99%**
    (Global 86.18 / Israeli 62.84). Best the arbiter can do.
- **Hard ceiling established:** overall caps at ~88.4% (perfect routing); 90%+ needs
  a better Global model, not arbiter tuning. See `THE_CEILING.html` & `SYSTEM_STATE.md`.
- Added `*_results.csv` to .gitignore
