XGBoost Re-Ranker: Vector Alignment Logic & Architectural Justification

How a 142-dimensional Global probability vector and a 13-dimensional Israeli probability vector are jointly queried to produce a unified feature space for a Pointwise Learning-to-Rank model.

Prepared for: B.Sc. Capstone Engineering Review  |  May 2026

1. System Overview

The Caleyez food-recognition system deploys two independently trained YOLO11l-cls convolutional classifiers: a Global Model covering 142 food categories and an Israeli Model specialising in 13 locally prevalent dishes. Each model produces, for a given input image, a full probability distribution over its own vocabulary — a softmax-normalised vector whose dimensionality matches the number of training classes.

Input Image RGB tensor
→
Global Model PG ∈ ℝ142
+
Israeli Model PI ∈ ℝ13
→
Re-Ranker XGBoost scores candidate set
→
Output argmax class

The central challenge this document addresses is: how do we combine signals from two incompatible probability spaces into a single, coherent feature vector that XGBoost can learn from?

2. The Old Architecture vs. the Re-Ranker

⬛ Old: Model Router (Flat Decision)

  • One row per image.
  • XGBoost classifies "use Global or Israeli?"
  • Discards the losing model's entire output.
  • Binary decision is irreversible; wrong routing loses all signal.
  • Cannot express "Global is 80% confident but Israeli is 95%."

✅ New: Pointwise Re-Ranker

  • Up to 10 rows per image (one per candidate class).
  • XGBoost scores "is this specific class correct?"
  • Both models' evidence is preserved for every candidate.
  • Gracefully handles vocabulary mismatches via zero-imputation.
  • Naturally fuses complementary signals into a single ranking.
Key insight: The router throws away information. If the Global model assigns 0.72 to "shawarma" and the Israeli model assigns 0.91, a hard routing decision must pick one and discard the other. The Re-Ranker sees both numbers simultaneously for the same candidate and lets the gradient boosting algorithm learn the optimal combination.

3. Candidate Set Construction

For each image, inference is run on both models. The Top-5 predicted classes from each model are extracted by descending probability. The two lists are merged into a unique candidate set of 5–10 classes: 

# Ordered: Global top-5 first, then any additional Israeli entries
seen       = set()
candidates = []
for cls in global_top5 + israeli_top5:
    if cls not in seen:
        seen.add(cls)
        candidates.append(cls)

One training row is generated per candidate. The binary target_label is 1 for the single candidate that equals the ground-truth class; all others receive 0. This formulation is Pointwise Learning-to-Rank: each item is independently scored and the rank is recovered by sorting scores at inference time.

4. Vector Alignment Logic — The Core Contribution

4.1 The Vocabulary Mismatch Problem

The Global model's probability vector PG has 142 entries; the Israeli model's PI has 13. Their vocabularies overlap but are not identical. A candidate class may be:

  • In both vocabularies — e.g., "falafel": present in both the Israeli model's 13-class vocabulary and the Global model's 142-class vocabulary.
  • Global-only — e.g., "apple_pie": present in the Global model, entirely absent from the Israeli model → israeli_prob = 0.0.
  • Israeli-only — e.g., "jachnun": a uniquely Israeli dish present only in the Israeli model, absent from the Global model → global_prob = 0.0.

A naïve tensor concatenation [PG ‖ PI] produces a 155-dim vector but destroys the semantic alignment between positions: index 87 in PG is "pizza" but index 87 would be out-of-bounds for PI. The two vectors live in incompatible index spaces.

4.2 The Aligned Query Approach

Rather than concatenating the full vectors, we query each vector by class name through the model's .names dictionary: 

# model.names  →  {index: class_string}  (e.g. {87: "pizza", 41: "hummus", ...})
# Inverted at startup into  class_to_idx = {class_string: index}

def prob_for_class(class_name, probs, class_to_idx):
    idx = class_to_idx.get(class_name)   # None if out-of-vocabulary
    if idx is None:
        return 0.0                         # ← explicit zero-imputation
    return float(probs[idx].item())

For every candidate class, two scalar values are extracted — one from each probability vector — and stored as global_prob and israeli_prob. The result is a semantically aligned feature pair regardless of the underlying vector dimensions.

Invariant: (global_prob, israeli_prob) always refers to the same candidate class. The feature space is 2-dimensional and fully aligned, regardless of whether either model's vocabulary contains the class.

4.4 Why Zero-Imputation Is Principled, Not a Hack

Setting israeli_prob = 0.0 for out-of-vocabulary classes is epistemically correct: the Israeli model has no evidence for a class it was never trained on. A probability of zero is the maximum-entropy (least informative) prior over an empty hypothesis, which is exactly the right starting point for a gradient boosting algorithm. XGBoost can learn, from training data, that a 0.0 in israeli_prob combined with a high global_prob is strong evidence for certain classes — effectively learning a soft version of the routing logic the old architecture tried to hard-code.

5. Feature Space Design

The feature space evolved across versions. v1 used 4 raw features. v4 (current) adds 5 engineered "evidence" features so the Arbiter can reason about each model's certainty, not just its raw prediction — the change that finally broke the Global-vs-Israeli accuracy trade-off.

5.1 Raw Features (v1 — per candidate)

FeatureTypeSourceSemantics
global_prob continuous [0, 1] PG[name→idx] Global model's posterior belief this candidate is correct.
israeli_prob continuous [0, 1] PI[name→idx] or 0.0 Israeli model's posterior belief; 0 if class is outside its vocabulary.
is_global_top1 binary {0, 1} argmax(PG) Whether this candidate is the Global model's single best prediction.
is_israeli_top1 binary {0, 1} argmax(PI) Whether this candidate is the Israeli model's single best prediction.

5.2 Engineered Evidence Features (v4 — confusion signals)

FeatureTypeScopeSemantics
global_entropy continuous [0, 1] per-image Normalized Top-5 entropy of PG (÷ log k). Low = peaked/confident, High = guessing.
local_entropy continuous [0, 1] per-image Normalized Top-5 entropy of PI (÷ log k). Same scale as global for direct comparison.
global_top1_vs_top2 continuous per-image Global decisiveness margin: p₁ − p₂. Large = unambiguous winner.
local_top1_vs_top2 continuous per-image Israeli decisiveness margin: p₁ − p₂.
arbiter_dominance_score continuous per-candidate global_prob − israeli_prob. Positive = Global favours it, negative = Israeli.
Why normalize entropy by log(k): The Global model (142 classes) and Israeli model (13 classes) have very different maximum entropies. Dividing by log(k) puts both on the same [0, 1] "confusion" scale, so the Arbiter can directly compare how uncertain each model is with a single learned threshold.
Why these features matter: With only the 4 raw features, the only way the Arbiter could help the Israeli minority was to globally lower its trust in the (majority) Global model — a zero-sum trade that hurt Global accuracy. The entropy features let the model make a conditional decision instead: "trust Global unconditionally when its entropy is low; only defer to Israeli when Global is genuinely confused."

6. Class Imbalance & Training Strategy

Two distinct imbalances had to be solved. The training pipeline evolved through four versions (full history in SYSTEM_STATE.md); the current v4 strategy is summarised here.

6.1 Candidate Imbalance (≈ 9:1) — scale_pos_weight

With a candidate set of ≈ 9 per image and at most one positive, the dataset is ~9:1 imbalanced. This is handled by XGBoost's scale_pos_weight: 

# scale_pos_weight = #negative / #positive  ≈  9.0  (identical in both domains)
params = {
    "objective":        "binary:logistic",
    "scale_pos_weight": n_neg / n_pos,   # ≈ 9.0
    "max_delta_step":   1,             # stabilises steps on weighted data
    "eval_metric":      ["logloss", "auc"],
}

6.2 Domain Imbalance (≈ 19:1) — 1:1 instance weighting

The training set has ~25,000 Global images vs ~1,300 Israeli — so Israeli rows were only ~5% of the data, and early models simply ignored the Israeli model. v4 fixes this with pure 1:1 domain-parity instance weights: each Israeli row is weighted by n_global_rows / n_israeli_rows so that sum(w_israeli) == sum(w_global) exactly.

v4 insight — weights balance, features decide. Earlier versions tried to fix the domain imbalance with ever-heavier weight multipliers, which over-corrected and wrecked Global accuracy (a zero-sum trade). v4 keeps weighting to a clean 1:1 parity and instead lets the engineered evidence features (§5.2 — especially global_entropy) decide when to trust each model. The Arbiter can now learn: "trust Global unconditionally when its entropy is low; only defer to Israeli when Global is genuinely confused."

Primary Evaluation Metric: Re-Rank Accuracy@1

Binary classification metrics (precision, recall) do not reflect real-world performance. What matters is: after re-ranking, is the correct class at position 1? 

def rerank_accuracy(df, score_col):
    # For each image, pick the candidate with the highest XGBoost score.
    best = df.sort_values(score_col, ascending=False)\
              .groupby("image_path").first()
    return (best["candidate_class"] == best["ground_truth_class"]).mean()

Additional reported metrics: Accuracy@3 (is ground truth in the top 3 re-ranked results?) and Mean Reciprocal Rank (MRR), which penalises the model for ranking the correct class further down the list.

7. Why Pointwise Re-Ranking Is Superior to Flat Routing

The table below summarises the architectural advantages across five dimensions:

Dimension Flat Router Pointwise Re-Ranker
Information used One model's top-1 only Full probability mass from both models, for all candidates
Decision granularity Model-level (binary) Class-level (scored per candidate)
Vocabulary mismatch Ignored / undefined Explicit zero-imputation; recoverable by the ranker
Training signal density 1 example per image ~9 examples per image (more data, richer gradients)
Extensibility Adding a 3rd model requires redesigning the router Add a new model3_prob column; retrain XGBoost
Conclusion: The Re-Ranker replaces a hard, irreversible routing decision with a soft, evidence-weighted scoring of every plausible hypothesis. It degrades gracefully (if XGBoost is uncertain, the original Global top-1 is preserved), scales to additional models trivially, and is evaluated with metrics that directly reflect end-user experience.

8. End-to-End Inference Protocol

At inference time (after the XGBoost model is trained and saved):

  1. Run both models on the input image.
  2. Extract the Top-5 candidates from each → merge → unique set of 5–10 classes.
  3. For each candidate, query global_prob and israeli_prob using the aligned lookup (zero-impute for OOV).
  4. Build a feature matrix of shape [num_candidates × 9] (4 raw + 5 evidence features).
  5. Score all rows with the XGBoost model → obtain a score vector.
  6. Return candidates[argmax(scores)] as the final prediction.

The entire re-ranking step adds negligible latency (a XGBoost inference over ≤ 10 rows is microsecond-scale) relative to the two CNN forward passes.
