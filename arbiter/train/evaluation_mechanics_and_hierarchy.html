Evaluation Pipeline & Hierarchical Misclassification Analysis

How the full Caleyez pipeline is evaluated end-to-end, and a rigorous analysis of why the XGBoost Re-Ranker favours highly confident broader classes over specific sub-classes — and how to detect it.

1. System Architecture Recap

The Caleyez inference stack is a three-stage pipeline. Each stage adds information; no stage discards the previous stage's output.

The evaluation script (evaluate_system.py) runs this full pipeline on every image in the test splits of both datasets and records the output of every stage.

2. Evaluation Script — How It Works

2.1 Dataset Scope

Two test directories are evaluated together in a single pass:

DomainDirectoryClasses
global datasets/general_model_data_set/test/142
israeli datasets/israeli-food-master/test/13

Each image is tagged with its domain (which dataset it came from) so the final accuracy summary can be broken down separately — overall system accuracy, accuracy on general foods, and accuracy on Israeli foods.

2.2 Per-Image Inference Steps

  1. Run Global YOLO → extract result.probs.data (142-dim tensor) → take Top-5 class names by descending probability.
  2. Run Israeli YOLO → extract result.probs.data (13-dim tensor) → take Top-5 class names.
  3. Merge into ordered unique candidate set (Global first, then any additional Israeli entries).
  4. For every candidate, query global_prob and israeli_prob via the aligned name→index lookup; zero-impute for out-of-vocabulary classes.
  5. Build an N×9 feature matrix (N = number of candidates; 4 raw + 5 evidence features) and score it with the XGBoost Booster.
  6. The candidate with the highest XGBoost score is the Arbiter Final Class.

2.4 Console Summary Output

After processing all images, the script prints three accuracy figures: Overall, Global domain, and Israeli domain. A large gap between the two domain accuracies immediately signals whether the Arbiter is biased toward one model's confidence scale.

3. The Hierarchical Misclassification Phenomenon

3.1 What Is It?

A hierarchical misclassification occurs when the system predicts a semantically correct but less specific class than the ground truth — for example, predicting "steak" when the ground truth is "filet_mignon". From a human perspective this is a soft error; from a classification metric perspective it is indistinguishable from predicting "sushi".

Observed example: The Global model assigned global_prob("steak") = 0.98 and global_prob("filet_mignon") = 0.61 for a filet mignon image. The Israeli model had no opinion on either class (israeli_prob = 0.0 for both). The Arbiter correctly maximised expected correctness — but the ground truth sub-class was never the highest-scoring candidate.

3.2 Mathematical Root Cause

The XGBoost Re-Ranker was trained to maximise Pointwise binary cross-entropy over individual candidate labels. Its score for candidate c given image x is:

score(c | x) = σ( F( global_probc, israeli_probc, is_global_top1c, is_israeli_top1c, global_entropy, local_entropy, global_top1_vs_top2, local_top1_vs_top2, arbiter_dominance_scorec ) )
where F is the XGBoost ensemble (9 features) and σ is the logistic sigmoid

At training time, label(c) = 1 iff c == ground_truth
∴ the model learns: high global_prob → high score(c)

For a broader class like "steak", the Global YOLO model has seen thousands of training examples spanning multiple steak sub-types (filet mignon, ribeye, T-bone…). Its softmax neuron for "steak" accumulates probability mass from all of these, producing a systematically higher and more confident output than the sub-class neuron.

Formally, let Cbroad = {filet_mignon, ribeye, T-bone, …} be the set of visual sub-classes that map onto the broader label "steak". Because the Global model was trained on flat (non-hierarchical) labels:

𝔼[ PG("steak") ] >> 𝔼[ PG("filet_mignon") ]

because "steak" is the attractor for a larger region of image space,
while "filet_mignon" only fires on a narrow sub-distribution.

∴ score("steak" | x) > score("filet_mignon" | x) for most steak images,
regardless of the true sub-class label.

3.3 Why the Arbiter Cannot Fix This Alone

The Arbiter was trained on the same flat label distribution. It learned that is_global_top1 = 1 combined with a high global_prob is the strongest predictor of correctness — because for the vast majority of training images, that combination is correct. The hierarchical sub-class images are a small, unseen minority in the training distribution.

3.4 Detecting Hierarchical Pairs in the Evaluation CSV

After running evaluate_system.py, the following pandas query isolates hierarchical misclassifications — rows where the Arbiter was wrong but the Global model was extremely confident: 

import pandas as pd

df = pd.read_csv("system_evaluation_results.csv")

# All errors where the arbiter had very high confidence
errors = df[(df["is_correct"] == 0) &
            (df["arbiter_final_score"] > 0.7)]

# Group by (predicted, truth) to find systematic confusion pairs
confusion_pairs = (
    errors
    .groupby(["arbiter_final_class", "ground_truth"])
    .size()
    .reset_index(name="count")
    .sort_values("count", ascending=False)
)

# Flag likely hierarchical pairs: high global confidence on the wrong class
hierarchical = errors[
    errors["global_top1_class"] == errors["arbiter_final_class"]
]
print(hierarchical[["ground_truth", "arbiter_final_class",
                    "global_top1_conf", "arbiter_final_score"]]
      .sort_values("global_top1_conf", ascending=False)
      .head(20))

This surfaces the top-20 cases where the Global model's top-1 prediction "won" against the ground truth with high confidence — the fingerprint of hierarchical misclassification.

4. Re-Ranker Training — Version History & Bias Correction Log

The XGBoost Re-Ranker went through five training iterations (v1 → v5) to resolve a severe domain imbalance. This section documents the exact failure mode of each version and the algorithmic change made to fix it.

4.1 v1 — Baseline: Global scale_pos_weight only

MetricValue
Overall Re-Rank Accuracy@184.90%
Global domain accuracy88.19%
Israeli domain accuracy28.20% ✗
Failure mode — Majority-Class Overruling Bias: The training set contained ~25,000 Global-domain images vs ~1,300 Israeli images. At ~9 candidate rows per image, Israeli rows were only ~5% of training data. XGBoost converged on the lazy rule "always trust high global_prob" — correct 95% of the time globally, but catastrophic for Israeli images. Out of 937 Israeli test errors, the Israeli YOLO was actually correct with >95% confidence in 836 of them — and the Arbiter overruled it every time.

4.2 v2 — Three-Layer Instance Weighting (over-corrected)

Three multiplicative weight layers were applied sequentially: (1) domain balance factor ~15.55×, (2) per-domain positive class balance, (3) high-confidence Israeli multiplier ×4.0 for correct rows, ×2.0 for wrong rows.

MetricValue
Overall Re-Rank Accuracy@169.53%
Global domain accuracy68.67% ✗
Israeli domain accuracy85.98% ✓
Failure mode — Compounding Weight Inflation: The three layers had no normalization guard. The observed weight diagnostics: sum(w_global) = 271,268 vs sum(w_israeli) = 593,979 — a domain ratio of 0.457, meaning Israeli rows carried 2.18× more gradient weight than Global rows. The Arbiter overcorrected and became "paranoid", constantly discarding confident Global predictions.

4.3 v3 — Normalize-Last Weighting

The core fix is a single mathematical guarantee appended after all multipliers: 

# Step 1: base domain balance
weights[is_israeli] = n_global_rows / n_israeli_rows

# Step 2: confidence redistribution WITHIN Israeli budget (modest ×1.5)
weights[high_conf_correct_israeli] *= 1.5

# Step 3: HARD RENORMALIZATION — the guarantee v2 was missing
weights[is_israeli] *= sum(weights[is_global]) / sum(weights[is_israeli])
# → sum(w_israeli) == sum(w_global) EXACTLY, always, no matter what step 2 did

Pos/neg balance Global scale_pos_weight Per-domain, baked into weights Global scale_pos_weight restored
Confidence multiplier None ×4.0 correct, ×2.0 wrong ×1.5 correct only (redistributive)
max_delta_step — — 1 (gradient step stabiliser)

v3 result — parity achieved, but still over-aggressive: Exact domain parity was reached and Israeli accuracy climbed to 84.14%, but Global accuracy only recovered to 74.9%. The structural problem: with only raw probabilities as features, the single lever available to help the Israeli minority was to globally reduce trust in the Global model — a zero-sum trade that necessarily damaged the majority Global domain.

4.4 v4 — Evidence-Based Routing (current)

v4 breaks the zero-sum trade-off by changing the inputs, not the weights. We stop fighting the imbalance with weighting tricks and instead give the Arbiter engineered confusion features so it can make a conditional trust decision rather than a blanket one.

The rule v4 lets the model learn: "If global_entropy is LOW (Global is peaked / confident) AND the Global top-1 is not an Israeli class → trust Global unconditionally. Only when global_entropy is HIGH (Global is genuinely guessing) should the Israeli signal be allowed to win." This is impossible to express with raw probabilities alone — it requires an explicit measure of each model's certainty.
New Feature (v4)ScopeMeaning
global_entropyper-image Normalized Top-5 entropy of Global, [0,1]. Low = confident.
local_entropyper-image Normalized Top-5 entropy of Israeli, [0,1].
global_top1_vs_top2per-image Global decisiveness margin (p₁ − p₂).
local_top1_vs_top2per-image Israeli decisiveness margin (p₁ − p₂).
arbiter_dominance_scoreper-candidate global_prob − israeli_prob for this candidate.
Why normalize entropy by log(k): The Global model has 142 classes and the Israeli model has 13, giving them very different maximum entropies. Dividing each by log(k) places both on the same [0,1] confusion scale — so the Arbiter can directly compare "how confused is Global" against "how confused is Israeli" with a single learned threshold.

Crucially, the heavy-handed confidence multipliers from v2/v3 are removed entirely. That signal now lives in global_entropy / local_entropy in a learnable, conditional form. Weighting reverts to pure 1:1 domain parity.

Reading these numbers correctly — precision is a red herring here. The "Correct" class shows high recall (0.91) but modest precision (0.65) at the 0.5 threshold. For a ranker this is exactly the right trade-off:
  • Recall 0.91 means the true candidate is given a high score 91% of the time — so it reliably surfaces near the top of the ranking. This is what actually drives Re-Rank Accuracy@1.
  • Precision 0.65 only says several other candidates also score > 0.5. That is harmless: at inference we take a single argmax per image, so non-winning false positives never become predictions. The 0.5 threshold is meaningless for a ranker — only the relative order of scores within an image matters.
No overfitting. Across 600 boosting rounds the train/eval AUC curves stayed locked together (final train-AUC 0.988 vs eval-AUC 0.983 — a gap of just 0.005), and eval-logloss kept decreasing monotonically. The shallow trees (max_depth = 5) plus subsample = 0.8 regularise effectively on this 9-feature space.

Why it underperformed — read the importances. The three raw probability features (global_prob, arbiter_dominance_score, israeli_prob) account for ~80% of total gain, while the engineered evidence features we added in v4 (global_entropy et al.) contribute only ~16% combined. The entropy signal — the entire premise of v4 — is present but not influential enough to implement the intended conditional rule ("trust Global when its entropy is low"). Meanwhile the 1:1 domain weighting still pushes the model to over-pick Israeli candidates on Global-domain images, which is exactly why Global accuracy fell below its baseline. The features were necessary but not sufficient; the weighting is still too aggressive for the majority domain.
Indicated next steps (see §5). (1) Relax domain weighting below 1:1 (e.g. weight Israeli to ~0.5× parity) so Global recovers toward its 88% baseline. (2) Add a gate: only let the Re-Ranker override the Global top-1 when local_top1_vs_top2 or israeli_prob is high — otherwise pass the Global prediction straight through. (3) Note Accuracy@3 is 93.95%, so the correct class is almost always in the candidate set — the remaining error is purely a top-1 ordering problem, which a gating rule can target directly.

4.6 v5 — Tunable Domain Dial + Interaction Features, and the Hard Ceiling

After v4, a full empirical study (an oracle analysis plus a sweep over domain-weight strength) was run on the real test set to find the true limits of the system. It produced the single most important result of the whole project:

90%+ overall is mathematically unreachable with the current two models. The bottleneck is the Global model itself, not the arbiter.

The proof is in these measured reference points (test split, 25,803 images):

PolicyOverallGlobalIsraeli
Always trust Global top-1 (no arbiter)83.73%88.19%0.00%
v4 (rigid 1:1 parity)80.33%80.41%78.85%
v5 (balanced, α=0.3) — shipped84.99%86.18%62.84%
PERFECT routing (oracle gate)88.40%88.19%92.26%
Oracle (true class anywhere in candidates)97.82%97.71%99.92%
Why the ceiling is 88.4%, not 90%. Global-domain images are 94.9% of the data, and the Global YOLO's own top-1 caps at 88.19%. An arbiter that only sees the two models' probability vectors cannot reliably beat a model's own argmax — empirically our best re-ranker reached only 87.3% on Global, below that baseline. So:

overall_max ≈ 0.949 × 88.19% + 0.051 × 92.26% = 88.40%

even with a perfect Israeli-vs-Global router. The 97.8% oracle is unreachable because it would require the arbiter to know the answer better than the models that produced the probabilities. To break 90%, the Global YOLO's top-1 accuracy must improve — that is now the highest-leverage work item, not further arbiter tuning.

The v5 design — make the trade-off an explicit dial

v4 was stuck at a bad operating point. v5 exposes the global↔israeli trade-off as a single hyperparameter and adds six interaction features derived from the existing columns (no dataset regeneration): 

# Domain-weight dial: israeli_row_weight = (n_global / n_israeli) ** ALPHA
ALPHA = 0.0   # no weighting → overall 85.6%, Global 87.3%, Israeli 54%
ALPHA = 0.3   # balanced (SHIPPED) → overall 85.0%, Global 86.2%, Israeli 63%
ALPHA = 1.0   # full parity (= v4) → overall 80.3%, Global 80.4%, Israeli 79%

# Interaction features (pure functions of the base 9 columns):
conf_global    = global_prob  * (1 - global_entropy)   # confident-and-correct signal
conf_israeli   = israeli_prob * (1 - local_entropy)
israeli_top1_p = israeli_prob * is_israeli_top1
global_top1_p  = global_prob  * is_global_top1
prob_ratio     = israeli_prob / (global_prob + 0.05)
both_agree     = is_global_top1 * is_israeli_top1

5. Proposed Future Mitigations

#1 lever — improve the Global model. The §4.6 ceiling analysis proves the arbiter cannot exceed ~88.4% while the Global YOLO's top-1 sits at 88.19% and represents 94.9% of traffic. Every mitigation below is a second-order refinement; the only way to reach 90%+ is to raise the Global model's own accuracy (more/cleaner data, longer training, a larger backbone, or better augmentation). Arbiter tuning has reached diminishing returns.
MitigationMechanismWhen to Apply
Class-specific score penalty Multiply the XGBoost score of known broad-class attractors by a discount factor δ < 1, boosting sub-class candidates. After identifying the top confusion pairs in the CSV.
Confidence entropy feature ✓ shipped in v4 H(PG) = −Σ p log p added as global_entropy / local_entropy (normalized by log k). High-confidence broad predictions have low entropy; XGBoost discounts them conditionally. Done — see §4.4.
Hierarchical label smoothing During Re-Ranker training, assign partial labels (e.g., target = 0.5) for classes that are hierarchically adjacent to the ground truth. Requires a hand-crafted class taxonomy (JSON).
Pairwise ranking loss Switch from Pointwise to Pairwise (XGBoost rank:pairwise) so the model learns to order sub-class above broad-class, not just score each independently. After validating the taxonomy.
Recommended first step: Run evaluate_system.py, apply the pandas confusion-pair query above, then inspect the top 10 pairs manually. If ≥ 5 of them are clearly hierarchical (broad vs. specific), proceed with the confidence entropy feature — it requires no label changes and can be validated in a single Re-Ranker retraining cycle.
