Finding 1 — The Global Model's Confidence Signatures

Mean top-1 confidence segmented by the correct routing decision reveals a critical asymmetry:

Arbiter LabelRouting DecisionGlobal Top-1 Conf (mean)Israeli Top-1 Conf (mean)
0Trust Global0.9530.741
1Trust Israeli0.7530.960
3Uncertain0.6830.771

When the Global model should be trusted (label 0), it averages 95.3% confidence. When it should not be trusted (label 1), it still averages a dangerous 75.3% — far above any naïve threshold. This validates the stated problem of "Overconfident Stupidity": confidence alone cannot route correctly. The cross-model rivalry signal (local conf vs. global conf) is required.

Finding 2 — The Israeli Model's Diagnostic Value

When the Israeli model should be trusted (label 1), its mean confidence reaches 96.0%, nearly identical to the Global model's best case. This means the Israeli specialist is not a weak fallback — it is equally decisive when its domain is in play. The arbiter's job is to detect when the Israeli model's high confidence should override the Global model's equally high (but wrong) confidence.

Finding 3 — Zero Label-2 Samples

The routing dataset contains no samples with arbiter_label = 2 (Global top-2 routing). This is a meaningful absence: the data generator determined that routing to the Global model's second prediction is never the best strategy — when the Global top-1 is wrong, the correct answer is either the Israeli model or an abstention. This simplifies the problem to a 3-class task: {0, 1, 3}.

Finding 4 — Model Training Trajectories

Global Model (97 epochs, 142 classes)
Peak val accuracy: 83.9% top-1 / 95.3% top-5 at epoch 68. Training loss descended monotonically from 3.01 → 0.139, but val loss increased from epoch 50 onward (0.719 → 0.843) — clear evidence of mild overfitting in the later epochs. This late-stage overfitting is one mechanism behind overconfident wrong predictions: the model memorised training-set feature patterns that do not generalise.
Israeli Specialist Model (63 epochs, 13 classes)
Peak val accuracy: 91.7% top-1 / 99.5% top-5 at epoch 59. Reached 85% top-1 by just epoch 11. The 13-class scope permits high precision with far fewer epochs. Val loss remained low (0.311–0.467 range) with no systematic divergence, indicating a well-generalised specialist.
Key insight for the Arbiter: The Israeli model is disproportionately reliable within its domain. The arbiter's primary job is not to decide "is the Israeli model good?" — it clearly is — but to detect when the image belongs to the Israeli domain.

Feature Engineering — Rationale & Mathematics

All 22 features are derived exclusively from the four confidence values and four class strings available at serving time. No ground-truth information is used.

3.1 Confidence Margins

The margin between a model's top-1 and top-2 confidence scores measures decision clarity. A large margin means the model is not just confident — it is dominantly confident. This is the first complement to raw confidence.

Python
# Global model decision clarity f["global_conf_margin"] = df["global_top1_conf"] - df["global_top2_conf"] # Israeli model decision clarity f["local_conf_margin"] = df["local_top1_conf"] - df["local_top2_conf"]

3.2 Entropy Approximation

Shannon entropy quantifies distributional uncertainty. Because only the top-2 softmax values are stored, a 2-term approximation is used. This captures cases where even the top-2 have a near-uniform distribution (high entropy = genuinely confused model):

Python
def _entropy2(p1: float, p2: float) -> float: """Shannon entropy approximated from the top-2 softmax probabilities.""" p1, p2 = max(p1, EPS), max(p2, EPS) return -(p1 * np.log(p1) + p2 * np.log(p2)) f["global_entropy"] = df.apply( lambda r: _entropy2(r["global_top1_conf"], r["global_top2_conf"]), axis=1 )

Justification: The Global model at label-3 (both wrong) has mean confidence 0.683 — still high, but its entropy is higher than at label-0. The entropy feature allows XGBoost to distinguish "uncertain-sounding confidence" from "decisive confidence."

3.3 Cross-Model Rivalry Features

The most powerful routing signal is the relative relationship between the two models' confidence scores on the same image:

Python
# Ratio > 1.0 signals: Israeli model is MORE confident than Global f["local_over_global_ratio"] = ( df["local_top1_conf"] / (df["global_top1_conf"] + EPS) ) # Signed difference — positive when Israeli model leads f["conf_diff_local_minus_global"] = ( df["local_top1_conf"] - df["global_top1_conf"] ) # Boolean: does local_top1 appear as global_top2? (convergence signal) f["global_top2_matches_local_top1"] = ( df["global_top2_class"] == df["local_top1_class"] ).astype(int)

The convergence signal (global_top2_matches_local_top1) deserves special mention: if the Global model's second-best guess matches what the Israeli specialist identifies as top-1, this is strong evidence that the image contains an Israeli dish that the Global model almost recognised but ultimately mis-classified.

3.4 Israeli Class Membership Flags

Python
ISRAELI_CLASSES = { "baklava", "bourekas_cheese", "falafel", "hummus", "jachnun", "malawach", "meorav_yerushalmi", "sabich", "samosa", "schnitzel", "shakshuka", "shawarma", "sufganiyah", } # Is the Israeli model predicting an Israeli-domain class? (strong bias signal) f["local_top1_is_israeli"] = ( df["local_top1_class"].isin(ISRAELI_CLASSES) ).astype(int) # Did the Global model map to an Israeli class (misfire or correct detection)? f["global_top1_is_israeli"] = ( df["global_top1_class"].isin(ISRAELI_CLASSES) ).astype(int) # Weighted Israeli signal — confidence * is_israeli f["israeli_signal"] = ( f["local_top1_is_israeli"] * df["local_top1_conf"] )

Note: the Israeli specialist model always outputs one of its 13 known classes — local_top1_is_israeli is always 1 by construction. However, global_top1_is_israeli varies and indicates whether the Global model spontaneously also mapped to an Israeli domain class, which is a different routing signal.

3.5 Global Class Israeli-Rate Encoding

For the 142 Global classes, a target-encoding is computed: what fraction of the time does each global class appear alongside a label-1 ground truth? This compresses per-class behaviour into a single numeric feature without creating 142 dummy variables.

Python
global_israeli_rate = ( df.groupby("global_top1_class")["arbiter_label"] .apply(lambda s: (s == 1).mean()) .to_dict() ) f["global_class_israeli_rate"] = df["global_top1_class"].map( global_israeli_rate ).fillna(0.0)

The "Overconfident Stupidity" Penalty

The core failure mode described in the problem statement — the Global model being semantically wrong at very high confidence — requires a purpose-built feature that triggers specifically in this regime.

Concrete example: A Tuna Tartare image classified as Bruschetta at 0.91 confidence (margin 0.87 over top-2). This is nutritionally catastrophic: Bruschetta macros are dominated by carbohydrates from bread while Tuna Tartare is high-protein/low-carb. Yet a threshold-based filter at conf > 0.8 would accept this prediction.

Mathematical Formulation

The penalty function is designed with three properties:

  1. Zero when confidence is moderate (< 0.85)
  2. Grows quadratically with confidence above the threshold
  3. Scales with the margin — a decisive wrong answer is worse than a hesitant one

Python
def _overconfidence_penalty( global_conf: float, global_margin: float, ) -> float: """ Penalty = conf² × margin if conf > 0.85, else 0. Quadratic growth ensures that a model at 0.99 confidence is penalised ~3.5× more than one at 0.85, correctly reflecting the greater risk. """ if global_conf > 0.85: return global_conf ** 2 * global_margin return 0.0 # Applied to the full dataset as a feature column f["global_overconf_penalty"] = df.apply( lambda r: _overconfidence_penalty( r["global_top1_conf"], r["global_conf_margin"] ), axis=1 ) # Interaction: penalty is amplified when the Israeli model is also firing f["global_overconf_x_israeli_conflict"] = ( f["global_overconf_penalty"] * f["local_top1_is_israeli"] )

The interaction term global_overconf_x_israeli_conflict is the most targeted feature in the entire set. It is non-zero only when the Global model is suspiciously over-confident and the Israeli specialist is also firing on a recognised dish — the exact scenario of "Overconfident Stupidity" applied to Israeli cuisine.

Israeli Class Protection & Strategic Bias

Protection is implemented at two levels: feature-level signalling (the features described above that make the Israeli routing signal visible to XGBoost) and training-time sample weighting that forces the model to pay disproportionate attention to the minority Israeli routing class.

5.1 Critical vs. Standard Israeli Classes

Not all Israeli classes carry equal nutritional risk if misclassified. The following five classes are designated as Critical because their macro-nutrient profiles differ most dramatically from plausible Global model confusions:

5.2 The Combined Distrust Score

A composite feature that summarises the argument against trusting the Global model, combining all the above signals:

Python
# Higher = stronger reason to distrust the Global model f["global_distrust_score"] = ( f["global_overconf_penalty"] * (1.0 + f["local_top1_is_israeli"]) - f["global_conf_margin"] # penalise decisive global predictions + f["local_over_global_ratio"] * f["local_top1_is_israeli"] )

This score is negative for well-calibrated Global predictions (high margin) and becomes strongly positive when the Global model is over- confident while the Israeli model is confidently predicting an Israeli dish.

Imbalance Handling — Sample Weights

With a 16.4× imbalance between label 0 and label 1, any standard unweighted classifier will achieve high overall accuracy by simply predicting label 0 everywhere — a strategy that is catastrophic for the application. Two complementary mechanisms address this.

6.1 Custom Sample Weight Formula

Python
WEIGHT_CLASS_1 = 18.0 # Base up-weight for Israeli-correct routes WEIGHT_CLASS_3 = 6.5 # Up-weight for uncertain routes CRITICAL_EXTRA_MULT = 2.5 # Additional multiplier for critical Israeli GT def compute_sample_weights( df_raw: pd.DataFrame, labels: np.ndarray ) -> np.ndarray: # Step 1: base weights by routing class w = np.where(labels == 0, 1.0, np.where(labels == 1, float(WEIGHT_CLASS_1), float(WEIGHT_CLASS_3))) # Step 2: extra multiplier for critical Israeli ground truths is_critical = df_raw["ground_truth_class"].isin(CRITICAL_ISRAELI).values w = np.where(is_critical, w * CRITICAL_EXTRA_MULT, w) return w.astype(np.float32)

Justification for WEIGHT_CLASS_1 = 18.0: The inverse-frequency weight would be 34185/2085 ≈ 16.4. A value of 18.0 slightly exceeds this to add strategic over-weighting of the minority class — necessary because the cost of a false-negative on label 1 (routing an Israeli dish to the Global model) is higher than the cost of a false-positive (routing a non-Israeli dish to the Israeli model, which typically returns a less-precise but numerically close estimate).

Justification for CRITICAL_EXTRA_MULT = 2.5: The 5 critical classes (jachnun, malawach, sabich, meorav_yerushalmi, shawarma) account for only ~42% of label-1 samples yet carry the highest nutritional error risk. The additional multiplier ensures these rare but high-impact cases are not diluted by the more common Israeli classes (falafel: 400 samples, samosa: 468 samples).

6.2 Why Not SMOTE or Class-Weight Dict?

SMOTE rejected: SMOTE generates synthetic samples by interpolating between existing feature vectors. For our feature space, which contains encoded class names (discrete), confidence ratios, and interaction terms, synthetic interpolation would create semantically invalid feature combinations (e.g., a sample that is "half hummus, half jachnun" in the class encoding space). Sample weighting is mathematically equivalent for tree-based models and preserves feature semantics.
XGBoost class weights rejected in favour of sample weights: XGBoost's scale_pos_weight is designed for binary classification. For multi-class problems, per-sample weights passed via the sample_weight parameter provide finer-grained control — specifically, the ability to assign different weights to individual critical-class samples within the same routing label.

XGBoost Architecture Choices

7.1 Why XGBoost?

The arbiter's feature space is moderate-dimensional (22 features), contains a mix of continuous and binary features, and has non-linear interaction structure (e.g., the overconfidence penalty only matters when the Israeli flag is also set). XGBoost's gradient-boosted decision trees handle all of this natively with no preprocessing.

Alternatives considered:

AlternativeRejection Reason
Logistic RegressionCannot capture the non-linear penalty × flag interactions without explicit polynomial features
Random ForestWeaker on imbalanced classes; no native early-stopping with sample weights in sklearn
Neural NetworkOverkill for 22 features; poor interpretability for academic justification
Rule-based thresholdBrittle; cannot capture the joint distribution of 22 features

7.2 Key Hyperparameter Decisions

ParameterValueJustification
max_depth7Deep enough to capture 3-way interactions (conf × israeli × margin); shallow enough to prevent overfitting on 41k samples
n_estimators600Low learning rate (0.05) requires more trees for convergence; cross-validation monitors for overfitting
min_child_weight5Prevents splits on fewer than 5 weighted samples — critical for minority class leaves
reg_lambda2.0Strong L2 regularisation to combat the label-0 dominance tendency
subsample0.8Row subsampling reduces variance and improves Israeli-class generalisation
colsample_bytree0.8Feature subsampling prevents the model from always using the same dominant features (global_top1_conf)

Evaluation Design

8.1 Why Macro-F1 as Primary Metric

Accuracy would be dominated by label-0 (81.9% baseline). Macro-F1 computes F1 independently for each class and averages, giving equal weight to the Israeli routing class (5%) as to the Global routing class (81.9%). This correctly penalises a model that ignores the minority.

8.2 Secondary Metric: Israeli F1

Label-1 F1 is tracked separately as the application's single most important metric. A model with good macro-F1 but poor Israeli F1 is rejected: it means the critical nutritional routing is failing.

8.3 Stratified K-Fold Cross-Validation

StratifiedKFold with k=5 ensures each fold maintains the original class distribution. This is essential given the 16.4× imbalance: random splitting could place all label-1 samples in a single fold. Out-of-fold predictions are aggregated for a single unbiased confusion matrix across the full dataset.

Python
skf = StratifiedKFold(n_splits=5, shuffle=True, random_state=SEED) for fold, (train_idx, val_idx) in enumerate(skf.split(X, y), 1): model_cv.fit(X_tr, y_tr, sample_weight=w_tr, ...) fold_pred = model_cv.predict(X_val) oof_pred[val_idx] = fold_pred # accumulate OOF predictions # Single confusion matrix from all OOF predictions (unbiased) cm = confusion_matrix(y, oof_pred, labels=[0, 1, 3])

Serving-Time Inference

The trained model is exported to the portable arbiter_xgb_model.json format. A predict_route() helper function accepts the raw inference outputs from both models and returns a routing decision with probabilities for the application layer:

Python
result = predict_route( model, meta, global_top1_class="bruschetta", global_top1_conf=0.91, global_top2_class="pizza", global_top2_conf=0.04, local_top1_class="jachnun", local_top1_conf=0.87, local_top2_class="malawach", local_top2_conf=0.08, ) # Expected output for the Tuna Tartare / Bruschetta scenario: # { # "route": 1, # "route_label": "israeli_top1", # "probabilities": {"global_top1": 0.11, "israeli_top1": 0.76, "uncertain": 0.13} # }

The arbiter_xgb_meta.json sidecar file records all feature names, label mappings, and Israeli class lists so that the serving environment can reproduce the exact feature engineering pipeline without importing the training-time constants.

Summary of Design Decisions

DecisionChoiceKey Justification
Routing task formulation 3-class classification {0,1,3} No label-2 samples exist; routing to global top-2 is never optimal
Primary evaluation metric Macro-F1 + Israeli F1 Accuracy is misleading under 16.4× imbalance
Feature for overconfidence Quadratic penalty × margin Targets the high-conf high-margin wrong predictions specifically
Israeli protection mechanism Sample weights + interaction features Dual protection: forces model to see the signal AND pay attention to it
Imbalance technique Custom per-sample weights Semantically valid for discrete features; finer than class-level dict
Model architecture XGBoost (gradient boosted trees) Handles mixed features, non-linear interactions, and weighted samples natively
Cross-validation StratifiedKFold-5 Preserves class distribution in each fold; OOF provides unbiased evaluation
SMOTE Rejected Interpolation of discrete encoded class names is semantically invalid
Entropy features 2-term Shannon approximation Only top-2 scores are available; captures distributional uncertainty beyond raw confidence
Global class encoding Target encoding (Israeli-rate) Compresses 142 classes into one semantic feature without dummy variable explosion
Engineering principle: Every design decision in this Arbiter prioritises recall on the Israeli routing class (label 1) over overall accuracy. A false-negative on label 1 — routing a Jachnun image to the Global model — produces a nutritional estimate that is off by as much as 45% in caloric value. No accuracy metric that treats this error equally to a label-0 confusion is fit for this application.
